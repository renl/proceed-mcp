## Boundary Verification and decomposition

Review scope: one combined Architect pass for this block, synthetic observation fidelity and sequencing. Source cross-check found the real defects: `protection.js` currently accepts `{path,ok,reason}`, launches bare `powershell.exe`, copies most parent environment and can protect existing directories. `path-trust.js` assumes Windows ancestry safe. Configuration/local credential/journal readers and ownership/operator-key paths skip required Windows admission. These are expected production gaps, not proposed semantics to preserve.

Normative metadata boundary: design "OS helper contract" is authoritative. Exact top-level `{version,account_sid,trusted_installer_sid,entries}`, exact per-target `{path,status,volume,object}`, exact object `{kind,attributes,owner_sid,control,dacl,aces}`, exact ACE `{type,sid,mask,flags}`. Version 1, complete ordered target correlation and canonical resolved SIDs are mandatory. Distinguish absent/unavailable, absent/null/empty DACL and unsupported ACEs. JavaScript validates complete observations before policy. No rename mapping, approval boolean or transferable admission certificate.

Real OS/process boundary: absolute trusted System32 PowerShell 5.1 and new-empty-directory-only `icacls.exe`, fixed metadata text, no shell/PATH/profile/script-file/policy bypass. Paths enter only through validated `PROCEED_ACL_TARGETS`. Query environment contains only validated `SystemRoot`/`WINDIR`, target input and an applicable preserved `PSExecutionPolicyPreference`. No token, arbitrary environment or secret contents. The design bounds each query and whole attempt to 20,000 ms with a 1,000 ms settlement reserve, 256 KiB output and at most 64 targets/32,768 UTF-8 input bytes per batch. Current units assert requested calls and refusal. Consumed-time, batch and settlement assertions are task 3.1. No network URL or new authentication protocol exists at this metadata boundary. Existing TLS-PSK and approval authority are unchanged.

Actual I/O order: syntax/prerequisites -> root and each admitted parent -> guarded configuration -> required objects -> authenticated reuse or exclusive ownership -> guarded local credentials/broker-only selected source -> journal recovery/expiry durability -> bind/final protection -> readiness -> Telegram workers. Reads require pre-admission and re-observation before return. New secret files require exclusive empty create -> inheritance admission -> bytes -> flush -> reverify -> publication. Existing destination, unknown entry or uncertain lock remains preserved. TUI sends no private authority before guarded config/key/ownership and authenticated connection.

User direction forbids ad hoc PowerShell test harnesses and PowerShell-only delivery prerequisites. No native diagnostic is planned or authorized. Current Linux-compatible units cannot qualify Windows itself. Source grounding reuses the design's pinned official Windows/Node references, not new research.
