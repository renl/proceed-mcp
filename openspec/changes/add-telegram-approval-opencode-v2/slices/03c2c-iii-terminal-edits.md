## Implementation brief

- Extend worker construction requirements with `recordControlsRetired`, `recordStatusShown`, `editMessageReplyMarkup`, `editMessageText`. Keep options/export unchanged. Preserve all C2b send behavior and canonical diagnostics.
- Process sends then sequential `presentationWork().edits`. Capture each entry and request. Controls payload is exactly `{chat_id,message_id,reply_markup:{inline_keyboard:[]}}`. Status is exactly `{chat_id,message_id,text:renderPortableRequestMessage(capturedRequest)}`. No parse_mode or authority. Core derives retirement before status per copy. Re-scan current work while running, never invent completion from a stale writer/noop return.
- Validate full accessible plain Message and plain chat, positive safe numeric date/chat/message IDs, addressed chat AND message ID. Boolean true, wrong tuple, date zero and not-modified rejection provide no success. Await the matching writer with captured request/decision/tuple and, for status, delivery state. No clock sampling for exact receipts. Re-derive ledger pair next scan after stale completion or a later ledger change.
- Reuse transient classification and 1/2/4/8/16/repeated30 second ladder with valid retry_after floor, scoped per tuple. Nontransient/invalid results block only that tuple and attempt the existing fixed redacted diagnostic. No edit failure rewrites presentation or delivery state. Unknown processing and storage stop remain distinct. Credential rejection fences all Telegram traffic while local status/cancel/wait/expiry stay usable.
- Stop fences new work/retries synchronously and aborts transport. An admitted valid late edit may enter its matching core writer and drain before close, including stale discard. No subsequent edit or timer after stop. Preserve partial-start cleanup and shared fence.
- Client edits accept optional `{signal}` and forward it to existing fixed-origin call. Runtime may require a complete UI client only if construction now canonically requires it. Preserve tokenless/local-only operation and existing lifecycle.
