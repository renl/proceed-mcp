## Implementation brief and Boundary Verification
- Category: normative public HTTP/MCP and cross-component ledger contract; actual wire is synthetic loopback `http://127.0.0.1:<configured-port>`, stdio MCP newline JSON-RPC revision `2025-11-25`. No Telegram/provider wire changes; live host/external credentials/network remain outside authorization.
- Preserve Origin403 → readiness503 → Bearer401 → owner-role403 → JSON-object parse400, max64KiB. Acknowledge: `POST /v1/requests/{request_id}/acknowledge`, owner Bearer + `X-Proceed-Request-Capability`, exactly `{decision_id}`. Closed body/raw `dec_`+32 lowercase hex validation400 precedes owner/path/capability authority404; unused reservations deny identically. No registration prerequisite, even with an irrelevant registration header.
- Returned: `POST /v1/requests/{request_id}/returned`, same owner/capability plus `X-Proceed-Registration`, exactly `{registration_id,decision_id}`. JSON parsing first; current owner/ID/secret/unexpired registration authentication401 precedes closed-body/decision validation400, then request authority404, serialized pending/mismatched decision409, flushed success200. Registration rejection is exactly `{schema_version:1,error:{code:"AUTH_REQUIRED",message:"registration authentication required",retryable:false}}`.
- Pending/mismatched well-formed decisions return `DECISION_MISMATCH`, retryable false, without clock sampling, expiry or append, even when due. Request authority denial is exactly `{schema_version:1,error:{code:"NOT_FOUND",message:"no such request",retryable:false}}`, HTTP404. Do not delegate evidence admission through an expiry-aware read.
- Await the accepted core result before HTTP200. First evidence uses its existing exact mutation/flush; duplicates append nothing. Return only the common request representation, no private timestamps. Ack confirms without fabricating returned evidence; returned can advance unavailable and cannot downgrade confirmed. Preserve initial outcome/identity, first independent timestamps and replay idempotency.
- Returned renews the captured authenticated registration only after whole success, including duplicate success; parse/auth/body/authority/conflict/storage failures never renew. Reuse registry fencing: expired or replaced incarnation cannot revive/renew replacement. A false renewal after committed evidence cannot undo or turn that commit into a failed evidence response.
- Existing source cross-check: HTTP acknowledge is an authority-only404 stub and returned has no route; this is the expected missing enablement, not an invented contract. MCP `execution.js` already forwards exact acknowledgement body/headers and maps HTTP/tool success/errors; do not edit it. Replace only stale acknowledgement-unavailable catalog/instruction meaning, preserving private retention, required terminal acknowledgement, assistant outcome reporting and `(request_id,decision_id)` deduplication. Waiting remains explicitly `ENHANCEMENT_UNAVAILABLE`; ack-tool success must not produce a returned report.
