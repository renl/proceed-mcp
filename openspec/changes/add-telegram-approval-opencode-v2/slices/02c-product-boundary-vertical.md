### Exact supported test-owned interception binding

The implemented gate is `tests/support/direct-host-gate.mjs`: one managed Node IPC child, **zero HTTP listeners**, direct authenticated HTTP to the unchanged host-owned canonical socket. Configure origin/auth once by private IPC. `select` binds exact path/ID; `exchange` carries method/path/body and a broker-incarnation-qualified serial. Only the matching successful admission is withheld; independent completion evidence precedes the `transportLoss` result. Subsequent broker exchanges are fenced until `discard-held` after broker stop; unrelated exchanges outside this deliberate restart fence retain real responses. No forwarding listener, alternate backend, fake origin, redirect, proxy, DNS substitution or auth termination. Existing forwarding fixture passes remain offline proxies only.

Supported process binding to finish after SE selects its client: launch **real CLI** as `node --import <test-owned-broker-preload> bin/proceed-mcp.js serve --state-dir <run-state>`. For a native `node:http` client, the preload intercepts `http.request` **only** at the configured host origin and supplies the ClientRequest/IncomingMessage-compatible callback/stream/error lifecycle via private IPC to this gate. It must preserve request bytes, method/headers/auth and error/abort timing; it may not alter production admission/reconciliation logic. If SE chooses fetch/Undici, SDET instead binds its supported dispatcher transport at the same seam and reviews parity before execution; SE is not required to choose a private HTTP library for this test. No incomplete preload is claimed implemented here. No production command flag or imported test module is authorized.

For MCP, `tests/support/product-receipt-relay.mjs` wraps **real** `node bin/proceed-mcp.js mcp --origin <id> --state-dir <run-state>` as the isolated host's configured local MCP command. `PROCEED_TEST_CHANNEL` names only a run-owned harness pipe/socket.
