3. **Confirm durable creation:** observe public status/owned GET representation pending and unexpired, correlate origin/session/client/request IDs, and verify commit-before-effect through the implementation's durability tests. 4. **Observe actual host timeout:** require host-side tool execution timeout/error evidence for that still-unresolved call and absence of successful completion. Merely sleeping after a prompt receipt or timer in an external test client is invalid. 5. **Resolve through real Telegram:** only after step 4, human presses the intended request's Approve/Reject or Respond plus actual correlated text (include approval-like text/whitespace). Assert one accepted resolution, exact text/type and unchanged requesting identity. No direct handler invocation, database decision fixture, public decision endpoint or terminal decision message.
6. **Confirm continuation:** match stable `msg_<request hex>`/persisted exact payload; validate admission, exact user history, successful inbox absence, then a subsequent assistant acknowledgement of request ID and correct outcome. Other session receives no decision input/acknowledgement. Capture baseline-to-result deltas, not unrelated preexisting turns.
7. **Reconcile/replay:** lose an admission POST response through a separate out-of-process HTTP fault without changing the immutable configured origin or destination. For the running-host spike preserve host, restart only broker with the same state, and replay/retry stable ID/text after inbox departure and after delivery. Compare resolution/response/origin/session/resolved_at before/after, assert one decision input and one decision-driven acknowledgement in the 30s window. Report bounded absence, not an unlimited exactly-once guarantee. HTTP fault implementation and containment require phase B tests/review; stdio receipt fault is not lost-admission proof.
8. Capture sanitized assertions and cleanup statuses, stop owned processes in finally, verify PID/listener absence and local namespace removal. Preserve candidate/version/case IDs and redacted hashes, not credentials/raw private prompts. Any failed or unobserved required case prevents spike PASS/allowlist admission and downstream broad integration.
