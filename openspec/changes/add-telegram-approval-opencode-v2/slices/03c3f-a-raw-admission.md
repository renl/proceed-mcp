- Both synchronous, total on JSON-shaped values, input-immutable, clock/broker/I/O-free. Unknown API fields neither grant authority nor invalidate otherwise admitted syntax. No polling, prompt send, ForceReply, copy selection, acknowledgement classification or consumer activation.

- Both require a plain update and raw safe-integer `update_id >= 0` whose next offset is safe. Failure is `invalid_update`. Callback refusal then has `callbackQueryId:null`. Text refusal has `userId:null,chatId:null`.
- Callback results: `{status:'ignored',reason:'not_callback_update'}` for absent/null callback. Nonplain callback is `invalid_callback`. Nonempty raw string query ID required, no trim, else `invalid_callback_id`. Preserve that ID only after validation.
- Other callback refusals: `{status:'refused',reason,callbackQueryId}`. Reasons `invalid_sender`, `invalid_chat`, `invalid_message`, `invalid_data` plus the preceding update/callback/id reasons.
- Require `callback_query.from` plain, `is_bot === false`, positive safe numeric `id`. Sender is NEVER `message.from`. Bot-authored request messages are valid. Require full accessible plain message with positive safe numeric `message_id` and `date`, plain private chat with independently positive safe numeric `id`. Convert actor/chat IDs with `String`, never require equality.
- Data must fully match `/^([art]):([a-f0-9]{32})$/` without trailing data/newline. Map a/r/t to approve/reject/respond. Success exactly `{status:'callback',kind,token,updateId,callbackQueryId,userId,chatId,messageId}`. Token is syntax, not request authority.
- Text ignored results exactly `{status:'ignored',reason}` with `not_message_update`, `edited_message` or `non_text_message`. Never use `not_update`. Require ordinary plain message, admitted non-bot sender, independently admitted private chat, positive safe message ID/date. Missing text is non-text, not caption inference.
- Text refusal exactly `{status:'refused',reason,userId,chatId}`. Actor fields are null until individually admitted. Reasons `invalid_update`, `invalid_sender`, `invalid_chat`, `invalid_message`, `invalid_text`, `malformed_command`, `invalid_reply_context`.
- Text must be raw nonempty well-formed Unicode, <=4096 scalar values, retained verbatim. No trim, normalization, case folding, approval inference or UTF-16-unit ceiling for incoming text.
- Reply context absent/null means null. Present context must be plain with positive safe numeric `message_id`. Its chat, if present/non-null, must be plain private with positive safe numeric ID and `String(id) === chatId`. Malformed context NEVER becomes absent, including on valid commands.
- Intent only if `text.startsWith('/respond')` and length is 8 or character 8 is ASCII space, tab, LF, CR or `@`. Exact grammar `/^\/respond (req_[a-f0-9]{32}) ([\s\S]+)$/`, entire remaining payload preserved, no trimming. Malformed intent never falls back to reply routing.
- Whole Message.text ceiling still applies to commands. Prefix is 46 scalars, so maximum payload is effectively 4050. Payload also obeys nonempty/well-formed/4096-scalar rule. Ordinary replies accept 4096 supplementary scalars.
- Common successful text fields: `{updateId,messageId,userId,chatId,text}`. Command adds `status:'command',requestId,replyPromptId` (null or positive prompt ID). Non-command with valid nonnull context adds `status:'reply',replyPromptId`. Without context use `status:'uncorrelated'`, with NO replyPromptId. No `/respondent`, leading whitespace, alternate case or unrelated space at character 8 command inference.
