### Callback binding and cursor ownership

Use `admitCallbackUpdate(update)`. An admitted callback has `{status:'callback',kind,token,updateId,callbackQueryId,userId,chatId,messageId}`. Resolve `correlateCallbackToken({callbackToken:token})` to null or `{request_id}`. This lookup includes mapped and terminal requests and grants no authority. Never infer an ID from text, work ordering, labels or public token views.

For a hit, pass exactly `{requestId:request_id,callbackToken:token,messageId,userId,chatId,callbackQueryId,updateId}` to `openResponse` for `kind:'respond'`. For approve/reject pass the same fields plus `resolution:'approved'|'rejected'` to `resolveCallback`. Core rechecks every authority/deadline/role binding inside serialization.

The result union is `{result:'refused'|'stale'}` or `{result:'retained'|'expired'|'recorded'|'open'|'opened',request}`. Raw/lookup/core refusal owns exactly one `advanceCursor(updateId)` before generic acknowledgement. Stale already-committed input gets no append and only neutral acknowledgement. Retained/expired/recorded/open/opened already own their cursor, never append another.

Use `answerCallbackQuery({callback_query_id,...})` for usable nonempty IDs, including refused/stale inputs. Exactly one best-effort UI attempt after the relevant core commit/install/wake, no business replay on UI failure and no receipt claim. Open/already-open is neutral. New recorded outcomes use exact prefix plus ledger suffix. Authorized retained/expired/cancelled targets use annex selection, never expose their outcome to a foreign callback. Only 401 credential rejection globally fences peers until restart. Genuine polling conflict keeps its own fatal rule.

### Text, pairing and raw grammar

Preserve `/start` and exact pairing flow first. Preserve malformed pairing-intent silence before generic text guidance, including canonical doubled-space, trailing-data/newline, bot suffix, uppercase code, tab and `x/pair` cases. Check any selected intent regex against existing C1P/C1PP cases and the new paired smoke, not a newly invented grammar. Never let malformed pair text fall through as response text.

Then use `admitTextUpdate(update)` and independently match the non-bot paired private tuple before any text writer. Unpaired/foreign text is silent cursor-only. Edited, caption and nontext input is silent. Invalid platform syntax must never reach an `INVALID_ARGUMENT` core call or stop the handler. Refused/uncorrelated paired response guidance follows its cursor commit.

For `{status:'reply'}`, call `resolveReply({messageId,userId,chatId,updateId,text,replyPromptId})`. For `{status:'command'}`, call `resolveCommand({messageId,userId,chatId,updateId,text,replyPromptId,requestId})`. Copy admitted fields exactly. Explicit absent command context is null. Unknown/present invalid context never becomes null or falls back to another writer. Preserve all legitimate text, even capability/token-like strings deliberately supplied by the human. Never trim, redact or infer approval. Apply the same result/cursor ownership as above. Uncorrelated text cannot choose a request by recency or displayed ID.

After committed text resolution, send the exact human-outcome composition to that admitted chat, without echoing response text or private authority. Retained/expired/cancelled text follows the same authorized annex selection. UI failure never replays its writer.
