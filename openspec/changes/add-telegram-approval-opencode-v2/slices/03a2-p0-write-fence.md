## Source-bound ordinary interfaces and expected behavior
- Existing `createPortableBroker({journal,owners,port,clock,logger,generateDecisionId})`; caller owns journal. `reserveHandle({ownerId,sessionLabel}) -> Promise<reservation>`, `readRequest({ownerId,capability,requestId}) -> Promise<request|null>`, `sweepExpired() -> Promise<{expired}>`, `status() -> Promise<status>`, `recover() -> Promise<{records}>`, `close() -> Promise<void>`. `snapshot()` and `pairing()` are synchronous copied last-installed views; no capability recovery.
- `Journal.open(path)`, `new Journal(path, ordinaryHandle, sequence)`, `recover() -> {transactions,validLength,fileBytes}`, `append(mutations)`, `sequence`, `close()` already exist. Ordinary handle observers delegate actual `write/sync/close`; no production injection seam added. Framing remains version 2 and sequence starts at 1.
- Every broker append rejection fences the journal before releasing serialization. Never install failed reserve/expiry, retry automatically, compensate, or infer rollback. All queued and fresh reserve/authorized-read/sweep/status turns recheck before time, decision IDs, append or successful return, including empty/unused-reservation observations. No new storage calls through fenced `recover()`; no in-place clearing.
- Preserve prequeue argument/authority denials: malformed/foreign read bindings return private null promptly even while append is held. Valid authority on an unused reservation normally returns null, but must not return stale success once fenced. Snapshot/pairing retain copied last-acknowledged state, not proof of disk rollback.
- Failures use existing private `CliError`, `code:STORAGE_FAILURE`, `exitCode:4`; first semantic failure retains `JOURNAL_STATE_INVALID/4`. Later failed semantic replay also fences and retains the complete prior installation. First failed recovery admits no writes. No exact error text or new public error is imposed.
- Recovery shares serialization with admitted operations. Reconcile only after quiescing/closing broker AND caller journal, normal `Journal.open` of the existing file, then a new broker's clock-free whole-history recovery. Retain complete valid records exactly once, discard only the approved incomplete final frame; never reset, drop valid frames, migrate or repair corruption.
- Selected durability binding for review: `Journal.recover` validates framing then delegates actual handle sync before acknowledging recovered sequence/result; authentic sync failure leaves its prior sequence unchanged. Broker refuses an unrepaired incomplete tail rather than treating tolerant framing output as readiness; normal reopen repairs it first. Successful sync plus semantic validation precede installation/acknowledgement.
- Design requires reconciliation/durability, not a new public recovery protocol. Architect must confirm the selected sync location, incomplete-tail `STORAGE_FAILURE/4`, terminal instance fence and serialized recovery binding; do not treat an engineering proposal as new normative authority. If rejected, return correction through coordination before implementation.
