## A executable runner-only contract

Harness public seam, not application API: `withLiveLifecycle(plan, driver)` from `tests/support/live-run-lifecycle.mjs`. Import has no effects. Resolve with `{assertion,cleanup,retained,code}`. Assertion is `passed|failed|blocked`, cleanup `passed|failed|not-needed`. `retained` is true once namespace reservation is attempted, including partial failure. Codes are fixed redacted harness categories, never raw exceptions. No application semantics, test endpoint or production import.

- Plan contains absolute worktree, `runId`, candidate40hex, port43189, environment allowlist input, limits and authorization. `runId` matches `^live-[a-z0-9-]{1,40}$`. Derive directory strictly as `<worktree>/.scratch/portable-live/<runId>` and state child `state`. No caller-supplied state override, reuse, restart or automatic alternate port.
- Authorization MUST have true `live`, `credentialAccess`, `consumeUpdates`, `exclusiveBot`, `noWebhook`, `privateHuman`, future finite `expiresAt`, and exact matching runId/port/candidate. Invalid/missing/expired/mismatched authority or invalid limits returns blocked/not-needed before ANY driver effect. These fields record external permission, not proof or permission granted by a flag. B requires a separately recorded authorization reference and reconciled owner confirmation. Never default them true in a live entry.
- All driver methods are async and test-only injectable effects. `preflight(context)` returns `{ready:true}` only on actual B checks. False/throw/timeout blocks without credentials or reservation. `reserve(context)` must return `{fresh:true,protected:true}` before credential acquisition. False/throw fails and enters cleanup of only resources actually owned. `acquireCredential(context)` returns a nonempty token in memory. `setup(context)` receives role environments. `execute(context)` receives no token or environments. Their fulfillment is runner success only, not independently verified application/live proof.
- Context has directory, state, port, candidate, deadline and AbortSignal. No raw plan/environment/authorization is forwarded. Setup alone additionally receives `environments:{broker,cli,mcp}`. Environment keys allowlisted from PATH/PATHEXT/SystemRoot/WINDIR/COMSPEC, plus TMP/TEMP/TMPDIR rooted at the run directory. Map acquired token only to broker `PROCEED_TELEGRAM_BOT_TOKEN`. No TELEGRAM_TOKEN inheritance, NODE_OPTIONS, password, proxy, host/provider credentials or token in CLI/MCP/model processes, argv, IPC, results or progress. B performs in-memory acquisition only from the explicitly authorized process credential source, not .env discovery.
- Order: preflight, setup progress, reserve, acquireCredential, setup, run progress, execute, teardown progress, stop, verifyStopped, complete progress. Refused preflight cannot claim readiness. After any attempted reserve, cleanup always runs, even when reserve, credential acquisition, setup, execute or progress persistence fails. Progress failure makes assertion failed but cannot skip teardown or leak raw diagnostics.
- Fixed live limits: aggregate600000ms including setup/run/teardown. Setup240000ms includes local readiness60000ms and human pairing180000ms. Run330000ms covers default Approve or explicitly authorized extension below. Cleanup30000ms reserves graceful10000, owned forced fallback5000 and verification15000. B outer watchdog630000ms. No deadline restart/extension. Every context carries a monotonic deadline within its phase and aggregate. Offline limits in fixture only shorten these for deterministic tests, never expose public deadline overrides.
- Phase timeout aborts its work. Cleanup gets an independent, initially un-aborted signal and reserved time, never the failed work signal. `stop(context)` graceful failure/timeout triggers `forceStop(context)` only for registered owned resources. Always attempt bounded `verifyStopped(context)`, requiring `{processesAbsent:true,listenerReleased:true,ownershipReleased:true}`. Residue or verification failure/timeout sets cleanup failed independently of assertion status. Force cannot remove locks or manufacture normal ownership release. Failed cleanup remains a blocker.
- `progress({phase,assertion?,cleanup?})` persists only allowlisted setup/run/teardown/complete categories and statuses. No stdout/stderr, error messages, token, pairing code, capability, private user/chat identity or accepted private text. B records safe request/decision/RPC IDs separately only after structural redaction. Never retain raw process output or RPC preparation frames.
- Driver owns resource registration before launch, partial-start cleanup, abort fencing and late-completion suppression. A must not call execute after failed setup or schedule new work during cleanup. No delete/reset/clear/drop effect exists. State, journal, private authority and evidence remain protected and retained on both outcomes pending explicit disposition.
