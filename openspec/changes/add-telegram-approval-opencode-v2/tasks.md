- **Durable encoding for the read-only decoder** (`state/journal.log`): 12-byte file header `"PROCEEDJ"` + `uint32be` format version 1, then frames of `uint32be` frame length | `uint32be` payload length | `uint64be` sequence (from 1, no gaps) | UTF-8 JSON payload | 32-byte SHA-256 over the frame bytes preceding the digest. Payload is `{schema_version:1, sequence, committed_at, mutations[]}` with mutation ops `pairing.set`, `pairing.challenge`, `pairing.challenge.consume`, `request.create`, `request.presentation`, `request.resolve`, `request.delivery`, `request.telegram`, `telegram.cursor`. A resolution and its exact outbox (prompt ID and prompt text) are one `request.resolve` record; a decision-carried Telegram update ID commits in the same record. The pending request representation projects from `request.create`; the outbox projection is `null` until a human `request.resolve` commits.
- **Flush ordering for effect observers**: every transaction is one frame written with `FileHandle.write` on an append handle followed by an awaited `FileHandle.sync()`; the broker applies the mutations and only then answers the HTTP request, sends a Telegram call or admits an OpenCode prompt. Recovery is a second `fsync` after a `FileHandle.truncate` of an incomplete tail (dedicated read/write handle because Windows cannot truncate an append-only handle). Reads compose from replayed state, never from a snapshot.
- **Client interception seam**: the OpenCode adapter is `src/opencode/client.js`; every origin call is `http.request(url-string, {method, headers, agent:false})` to the immutable configured `http://127.0.0.1:<port>` with `Authorization: Basic base64("opencode:"+password)`, a 10s `request.setTimeout`, and a JSON body with explicit `content-length`. Response bodies are read from the `IncomingMessage` stream with a 4 MiB bound. The Telegram client is the only `https` user and targets the fixed `https://api.telegram.org` origin. There is no production test flag, injected module hook or test-only route.
- Awaited-flush evidence required by `assertCommitBeforeEffect`/`assertFlushedBeforeEffects` therefore binds to `FileHandle.sync` completion plus the production commit acknowledgement; pending commit must be observable before the create response, and the decision record before the Telegram acknowledgement and before the prompt POST. Broker readiness for bindings is an authenticated `GET /v1/status` with **`credentials/control.token`**; owned reads use the per-origin credential. Broker port comes from `config.json` `broker.port`.
